# 🔒 Безопасность AutoStars

Документ о том, какие секреты и деньги находятся в контуре программы, что сделано
для их защиты и что обязан сделать владелец. Читать перед первым запуском.

## 1. Что защищаем

| Актив | Где лежит | Что будет при утечке |
|---|---|---|
| `FUNPAY_GOLDEN_KEY` | `.env` | доступ к аккаунту продавца FunPay: вывод средств, изменение лотов, переписка с покупателями |
| `GAMEAU_API_KEY` | `.env` | покупка звёзд за ваш баланс USDT, т. е. прямые деньги |
| `TELEGRAM_BOT_TOKEN` | `.env` | чтение ваших алертов и **команд управления** (если угадан chat_id) |
| баланс GAMEAU (USDT) | на стороне GAMEAU | списание на выдачу звёзд посторонним |
| база `autostars.db` | локально | ники и суммы заказов покупателей; ключей там нет |

## 2. Секреты в коде и в выводе

- **Только `.env` / переменные процесса / `config.json`** — никогда в аргументах
  командной строки (аргументы видны в `ps`/журналах планировщика) и никогда в коде.
- `.env` в `.gitignore`; в репозитории — `.env.example` с заглушками. Заглушки
  (`paste_…`, `your_…`) движок считает «не задано» — нельзя случайно «запустить
  с тестовым ключом» и решить, что всё настроено.
- **Маскирование в выводе** (`autostars/security.py`): `mask_secret()` оставляет
  первые и последние 4 символа (`abcd…********…wxyz`), `redact()` вычищает из
  произвольной строки `golden_key=…`, `"api_key": "…"`, `csrf-token`, `Bot
  <token>`. Применяется в логах, в `--config-show`, в Telegram-алертах.
- Консольный лог пишется в **stderr** — чтобы `--stats --json > report.json` не
  протёк в файл, который потом прикладывают к тикету.
- Файловый лог ротируется и не содержит ключей; но содержит **номера заказов,
  ники покупателей и суммы** — это тоже чувствительно (см. §6).
- GUI: поля секретов пустые, значение не подставляется; пустой ввод = «не менять»;
  «Сохранить» пишет в файл только реально изменённые значения; пароли не
  отображаются даже в логе процесса.

### Проверено тестами

`tests/test_security_paths.py` — шаблоны redact (включая JSON и URL Telegram),
маскирование, отсутствие секретов в `to_safe_dict()`. `tests/test_cli_smoke.py` —
`--config-show` не содержит значений ключей.

## 3. Права доступа и размещение файлов

```bash
chmod 600 .env autostars.db                 # владелец — только чтение/запись
chown autostars:autostars /var/lib/autostars  # сервис работает не от root
setfacl -p -m "u:autostars:rw-" …            # если используется ACL
```

- Не храните `.env` в облачных папках (Dropbox/OneDrive) и не синхронизируйте
  каталог проекта; `autostars.log` и `.env.bak` туда же — бэкап настроек содержит
  **прежние ключи**.
- После `install.bat`/правок GUI, если меняли ключ, `.env.bak` можно удалить:
  `rm .env.bak` (Windows: `del .env.bak`).
- Docker: том `./data` держите в каталоге с правами `700`; не копируйте `.env` в
  образ (compose читает его с хоста).
- systemd-юнит использует `EnvironmentFile` + `ProtectSystem=full` + `NoNewPrivileges`;
  при смене ключа — `systemctl restart autostars` (значения перечитываются при старте).

## 4. Конфигурация: кто кем может стать

Приоритет: **переменные процесса → `.env` → `config.json` → код**.

Практический смысл: оператор (systemd `Environment=`, `docker run -e`) всегда
переопределит файл. Если кто-то получит запись в `.env`, он сможет **выключить**
защиты: `DEFAULT_MAX_CHARGE_USDT`, `MAX_CONCURRENT_ORDERS`, `LOW_BALANCE_THRESHOLD_USDT`.
Поэтому запись в папку приложения = права на деньги; не отдавайте её
веб-серверам и «удалённым помощникам» — вместо этого выдайте `--check`/`--report`.

`--config-show` показывает применённые значения и файлы-источники — первый шаг
при разборе «почему бот работает не так».

## 5. Деньги: механизмы, которые нельзя обходить

| Механизм | Защита от |
|---|---|
| `Idempotency-Key = uuid5(номер заказа)` | двойная покупка при ретраях/повторном запуске |
| `maxCharge` (+ `MAX_CHARGE_MARGIN_PCT`) | списание больше согласованного при скачке цены (409 `PRICE_CHANGED` → заказ не создан) |
| запрет повтора бизнес-ошибок | «купить ещё раз, потому что запрос не понял» |
| идемпотентность по БД (`orders`) | повторная выдача уже обработанного заказа, дубль ответа покупателю |
| `--test-order` без `-y` не запускается | тестовая покупка «в пустую» на реальные USDT |
| `--dry-run` | расчёт сметы без запроса к API |
| `LOW_BALANCE_THRESHOLD_USDT` + алерт | выдача в момент, когда USDT на исходе |
| `--pause` | приём новых заказов во время обслуживания/разбора |

Поправки в этих местах требуют теста и упоминания в PR (см. `CONTRIBUTING.md`, §10).

## 6. Данные покупателей и логирование

В БД и логах остаются: номер заказа FunPay, `@username`, `chat_node`, количество
звёзд, суммы. Это минимум, необходимый для выдачи и для вразумительной поддержки
GAMEAU. Чего нет и не должно быть: переписка, cookies, токены, письма, телефоны.

Срок хранения: лог живёт, пока не вытеснится ротацией (5 МБ × 5 файлов), база —
бессрочно (история сделок нужна для статистики и разборов с поддержкой GAMEAU). Удалить данные покупателя:

```sql
DELETE FROM orders WHERE username = '@ник';
DELETE FROM task_events WHERE order_id = '…';
```

Перед публикацией скриншотов/логов (issue, чат поддержки) — прогоните файл через
`python -c "from autostars.security import redact; print(redact(open('autostars.log').read()))"`.

## 7. Внешние границы

- Входящих портов нет: FunPay — исходящий HTTP + long polling `runner/`,
  Telegram — long polling `getUpdates` (не вебхук). Не нужно ни TLS-сервер, ни
  домен, и наружу ничего не торчит.
- Команды бота принимает только `TELEGRAM_CHAT_ID` владельца; всё остальное
  игнорируется без ответа. `/stop` и `/retry` не работают «от покупателя».
- Ответы FunPay/GAMEAU разбираются защитно: отсутствие поля/неподходящий тип не
  приводит к исполнению стороннего кода (никаких `eval`, шаблонизаторов, `shell=True`).
- `subprocess` в GUI (`bridge.run_cli`) строит команду из белого списка флагов CLI
  и не принимает пользовательский текст как аргументы.
- Шифрование канала — обычный TLS; для само-проверяющихся запросов прокси не
  поддерживаются (и не включайте «MITM-анализ HTTPS» в антивирусе: он ломает
  csrf-сессию FunPay, см. INSTALL.md).

## 8. Зависимости и сборка

| Пакет | Почему он | Правила |
|---|---|---|
| `httpx` | async HTTP/2, пул соединений | диапазон в `pyproject.toml`, обновление — через CI |
| `aiosqlite` | SQLite без блокировки event loop | то же |
| `beautifulsoup4` | парсинг HTML FunPay | то же |
| `flet` (extra `gui`) | десктоп-интерфейс | **закреплён `<1`**: API 1.x несовместим |
| `FunPayAPI` (только legacy) | сторонняя обёртка FunPay | не входит в ядро; в CI ставится `--no-deps` |

- В `requirements.txt` — рантайм-минимум, в `pyproject.toml` — extras; «случайных»
  зависимостей в коде нет (проверяется CI-установкой ядра без extras).
- Локальная копия зависимостей: `pip freeze > lock.txt` перед релизом exe.
- `.exe`: PyInstaller one-file. Подписи кода нет — SmartScreen и антивирусы
  реагируют на упаковщик ([docs/WINDOWS_BUILD.md](WINDOWS_BUILD.md)). Не
  распространяйте билд, собранный на чужой машине, и не берите «готовые exe» из
  чатов: единственный воспроизводимый путь — `build.bat` из этого репозитория.

## 9. Риски площадки и права

- Автоматизация действий на FunPay может противоречить правилам площадки —
  ответственность на владельце аккаунта; используйте отдельный продавец-аккаунт и
  не запускайте бота с браузера, в котором вы «вручную» отвечаете покупателям.
- GAMEAU — сторонний B2B-сервис: меняются цены, лимиты, статусы. Программа не
  хранит их состояние офлайн: при недоступности каталога используется оценка
  `USDT_PER_1000_STARS`, и `--check` об этом честно скажет.
- Завод USDT (Whitebird/P2P) — финансовые операции с соответствующими
  налоговыми/банковскими рисками; курс зашивается в `RATE_VARIANT_*` и влияет
  только на **отчётность**, не на факт списания.
- Юридически это «инструмент продавца», а не «сервис продажи звёзд»: лицензия MIT,
  без гарантий.

## 10. Чек-лист перед публикацией/обновлением

- [ ] `git grep -nE "(golden_key|api_key|bot_token)\s*=\s*['\"][A-Za-z0-9_:-]{16,}"` — пусто
- [ ] в истории нет `.env`/`autostars.db`/`autostars.log` (`git log --all --stat | grep -E "\.env$|autostars\.(db|log)"`)
- [ ] `python -m pytest -q` зелёный, включая тесты маскирования
- [ ] `autostars --config-show` не показывает ключи целиком
- [ ] в свежем логе (`-v`, `--once`) ключей нет: `grep -E "golden_key|api_key" autostars.log`
- [ ] `.env` на сервере `chmod 600`, владелец — сервисный пользователь
- [ ] включён `--pause` на время обслуживания; после — `--resume`
- [ ] алерты приходят (тест: `autostars --stats-push` при настроенном Telegram)
- [ ] бэкапы: `.env` и `autostars.db` ( скопировать в защищённое место, не в git)
